# 02. Epidemiological quality control

## Objective

Apply epidemiological quality control criteria to the complete master metadata table in order to generate a curated dataset suitable for downstream genomic analyses.

This step removes records that do not meet the minimum epidemiological and genomic metadata requirements of the RSV Analysis Pipeline.

The resulting dataset is the common starting point for both national surveillance and custom analyses.

## Input

The input is the master table generated during Step 01:

```text
results/01_master_table/master_table.tsv
```

This table contains the complete integrated metadata dataset before epidemiological filtering.

## Processing

Epidemiological quality control is performed using `genometabletools filter`.

The following criteria are applied:

| Filter | Description |
|---|---|
| `Host=Human` | Keep only human samples |
| `Collection date notna` | Remove records without a collection date |
| `Location notna` | Remove records without geographical information |
| `autonomous_community notcontains Unknown` | Remove records without a curated Spanish autonomous community |
| `Lineage notna` | Remove records without lineage information |
| `Genotype notna` | Remove records without genotype information |
| `Sequence Length>=13700` | Keep sequences with a genome length of at least 13,700 nt |
| `Additional host information notcontains same patient` | Remove records identified as additional longitudinal samples from the same patient |

All filters are applied sequentially to the complete master table.

The minimum sequence length of 13,700 nt corresponds approximately to 90% of the RSV genome and provides an initial genome completeness criterion before sequence-level QC.

## Output

The output is generated under:

```text
results/02_epidemiological_qc/
```

Main output:

```text
results/02_epidemiological_qc/qc_epi_table.tsv
```

`qc_epi_table.tsv` contains the records that pass all epidemiological quality control criteria.

## Software

This step uses:

- GenomeTableTools

Filtering is performed using `genometabletools filter`.

## Run

Execute Step 02 with:

```bash
bash workflow/02_epidemiological_qc/run.sh
```

Step 02 requires the master table generated by Step 01.

If necessary, generate it first with:

```bash
bash workflow/01_metadata_integration/run.sh
```

## Downstream use

The resulting `qc_epi_table.tsv` is the shared source dataset for Step 03 — Dataset selection.

For the national surveillance workflow, Step 03 applies the predefined national dataset selection criteria.

For custom analyses, Step 03 applies user-defined filters to this same epidemiologically curated dataset.

For example:

```bash
bash run_pipeline_custom.sh valencia \
    --where "autonomous_community=Comunitat Valenciana"
```

This architecture ensures that national and custom analyses start from the same epidemiologically curated source dataset while allowing the downstream genomic dataset to be defined independently.

## Notes

The records removed during this step remain available in the original:

```text
results/01_master_table/master_table.tsv
```

The complete unfiltered master table can be inspected using:

```bash
bash run_pipeline_master_table_raw.sh
```

which generates the raw GenomeReport under:

```text
results/99_raw_report/
```

The sequence length filter applied here is an initial metadata-based completeness criterion. Additional sequence-level quality control is performed later in Step 04.
